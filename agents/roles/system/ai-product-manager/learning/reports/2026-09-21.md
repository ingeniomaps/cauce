## Hallazgos

**H1 — El 2026-09-18, la Compliance API de Anthropic sumó a sus endpoints de sesión local las transcripciones
de sesiones de Claude in Chrome (`product_surface: claude_in_chrome`), en beta para organizaciones Claude
Enterprise, sin necesitar una Compliance Access Key ni un scope nuevos.** [Verificado] Entrada del
2026-09-18 en `platform.claude.com/docs/en/release-notes/overview`, leída el 2026-09-21: «The Compliance
API local session endpoints now also return transcripts of Claude in Chrome sessions (`product_surface`
value `claude_in_chrome`), in beta for Claude Enterprise organizations, with your existing Compliance
Access Key and the `read:compliance_user_data` scope.» Corroborado de forma independiente por búsqueda web
del 2026-09-21 (creatorstoolbox.com, releasebot.io): misma fecha de anuncio, y la cobertura describe los
tres endpoints (`GET /v1/compliance/apps/sessions/local` y sus dos variantes) como reutilización del
mismo acceso que ya cubría sesiones de Cowork y Claude Code.

**H2 — El 2026-09-14, la Messages API sumó compactación de conversación a demanda (beta,
`compact-2026-09-04`): se manda el parámetro `compaction` y la API devuelve un bloque firmado que resume
los mensajes enviados, para reenviarlo en vez de esos mensajes en pedidos siguientes.** [Verificado]
Entrada del 2026-09-14 en la misma página, leída el 2026-09-21: «Send the top-level `compaction`
parameter, and the API returns a signed `compaction` block that summarizes the messages you sent. On
later requests, send that block first, in place of those messages.» La misma entrada documenta que quien
llama elige cuándo compactar, que el pedido puede correr en background, y que en modelos con thinking
preservado el thinking de los turnos que se mantienen palabra por palabra puede seguir siendo válido.
Corroborado de forma independiente por búsqueda web del 2026-09-21 (mlpills.substack.com y el tracker
`sahuagin/mu`): misma fecha y mismo header beta. Este hallazgo no apareció en el informe del 2026-09-14

## Posibles prácticas obsoletas

- Un system contract (paso 5 del flujo de este cargo) que gestione el contexto recortando o resumiendo la
  conversación a mano, en vez de usar el bloque de compactación firmado que ofrece la Messages API en beta,
  pierde una forma de mantener costo y latencia previsibles sin perder los turnos recientes palabra por
  palabra (H2).
- Un readiness check (paso 7 del flujo) sobre logging minimizado y compliance que asuma que las sesiones de
  Claude in Chrome no dejan transcript recuperable queda desactualizado para organizaciones Claude
  Enterprise con Compliance API habilitada (H1).
- Un runbook de seguridad de acceso que no distinga entre keys de service account y keys de proyecto con
  dueño pierde el control que ahora existe para restringir cuáles se pueden crear a nivel organización o
  proyecto (H3).
- El enlace roto de H6 no es una práctica nueva: es el mismo hallazgo del 2026-08-31, del 2026-09-07 y del
  2026-09-14, todavía sin decidirse en ninguna propuesta mensual (H7).

1. Corregir el enlace de H6 (el mismo H7 del 2026-08-31, H8 del 2026-09-07 y H10 del 2026-09-14) en

   que ya usa `learning/sources.yaml:13`. Es el cuarto informe consecutivo que lo registra sin que ninguna
   propuesta mensual lo haya decidido (H7).
2. Si en una instancia real (no este toolkit) hay un contrato de sistema que gestiona el contexto de forma
   manual, evaluar si la compactación a demanda de la Messages API (H2) simplifica ese manejo antes de
   seguir manteniendo la solución propia.
3. Si en una instancia real hay un piloto o producto que use Claude in Chrome bajo Claude Enterprise,
   documentar en el readiness check que sus sesiones ya son recuperables vía Compliance API (H1), lo que
   puede cambiar el diseño de logging minimizado.
4. Si en una instancia real hay API keys de OpenAI compartidas entre personas o servicios, evaluar si
   restringir su creación a service accounts o a keys de proyecto con dueño (H3) reduce superficie de
   riesgo de credenciales.
