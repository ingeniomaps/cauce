`platform.claude.com/docs/en/release-notes/overview`, leída el 2026-09-14: «Claude Managed Agents
permission policies now include `auto`: the server evaluates each agent or MCP tool call and runs it,
denies it, or pauses for your approval. `agent.tool_use` and `agent.mcp_tool_use` events report how each

## Posibles prácticas obsoletas

- Un system contract (paso 5 del flujo de este cargo) que modele el control humano sobre Claude Managed
  Agents con sólo dos niveles —`always_allow` corre todo, `always_ask` pausa todo— deja afuera la opción
  intermedia `auto`, que evalúa caso por caso y es relevante al elegir nivel de automatización (paso 4 del
  flujo: sugerir/redactar/recomendar/decidir/actuar) y al diseñar oversight humano genuino (H1).
- Un pilot o journey (paso 8 del flujo) que asuma que sólo hay visibilidad de sesión vía la Consola web
  pierde la alternativa de terminal en vivo con `ant beta:sessions connect` para aprobar o denegar llamadas
  (H2), que puede simplificar el soporte y el incident path de un piloto con Managed Agents.
- El enlace roto de H10 no es una práctica nueva: es el mismo hallazgo del 2026-08-31 y del 2026-09-07,
  todavía sin decidir en la propuesta mensual archivada (H11).

   propuesta mensual lo haya decidido (H11).
2. Si en una instancia real (no este toolkit) hay un contrato de sistema vigente sobre Claude Managed
   Agents, evaluar si `auto` reemplaza o complementa `always_ask` para las tool calls de mayor riesgo, y
   documentar esa elección en el system contract junto con el criterio de escalamiento (H1).
3. Si en una instancia real hay un piloto con Managed Agents, considerar `ant beta:sessions connect` como
   canal de soporte/incident path en vez de (o además de) la Consola web (H2).
4. Si en una instancia real hay un producto de voz o un contrato que asuma la Realtime API previa,
   revisar si migrar a GPT-Live-1 GA cambia el system contract (latency, costo por minuto, fallback) antes
   de tratarlo como reemplazo directo (H4).

investigación, no edición del cargo.
