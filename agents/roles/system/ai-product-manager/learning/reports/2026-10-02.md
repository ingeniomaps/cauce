## Hallazgos

**H1 — El 2026-09-28, Anthropic lanzó Claude Sonnet 5.5 (`claude-sonnet-5-5`), con el mismo precio que
Claude Sonnet 5 ($2/$10 USD por MTok).** [Verificado] Entrada del 2026-09-28 en
`platform.claude.com/docs/en/release-notes/overview`, leída el 2026-10-02: «We've launched Claude Sonnet
5.5 (`claude-sonnet-5-5`). It's available on the Claude API, [...] Amazon Bedrock, [...] Claude Platform on
AWS, [...] Google Cloud, and [...] Microsoft Foundry.» Corroborado de forma independiente por búsqueda web
del 2026-10-02 (siliconangle.com, 9to5mac.com, unite.ai): genera salida más del 30% más rápido y hasta 30%
más económico en las pruebas de Anthropic, mantiene el precio de Sonnet 5 ($2/$10 por MTok) y, según
unite.ai, iguala a Opus 5.5 en benchmarks de conocimiento usando a menudo menos tokens.

**H2 — El mismo lanzamiento rompe compatibilidad hacia atrás frente a Sonnet 5 en cinco puntos: para
desactivar el thinking hay que mandar `thinking: {"type": "between_tools"}` en vez de `"disabled"`, y sólo
funciona con `effort` en `high` o menor; `tool_choice` de tipo `any` o `tool` devuelve 400; los bloques de
thinking quedan atados al modelo y a la conversación; en la Claude API y Google Cloud ya no se acepta la
tool `computer_20251124`; y la advisor tool rechaza a Claude Opus 4.8, Claude Opus 4.7 y Claude Sonnet 5
como advisors. Además, los bloques de thinking que produce Sonnet 5.5 sólo funcionan en la cuenta que los
produjo o en una cuenta vinculada: desde otra cuenta, la API descarta el bloque antes de que el modelo lo
vea y el pedido sigue adelante igual.** [Verificado] Misma entrada del 2026-09-28, leída el 2026-10-02, con
remisión a la guía de migración de Sonnet 5.5.

**H3 — El 2026-09-30, Anthropic deprecó Claude Sonnet 4.5 (`claude-sonnet-4-5-20250929`), con retiro
programado para el 2026-11-30 y migración recomendada a Claude Sonnet 5.5.** [Verificado] Entrada del
2026-09-30 en la misma página, leída el 2026-10-02.

**H4 — El 2026-09-24, además del cambio de facturación de refusals ya registrado como H6 del informe
anterior, la Compliance API sumó dos cambios que ese informe no capturó: los endpoints de sesiones locales

## Posibles prácticas obsoletas

- Un system contract (paso 5 del flujo) que fija `thinking: {"type": "disabled"}` para un modelo Sonnet se
  rompe con un 400 al migrar a Sonnet 5.5: hace falta `thinking: {"type": "between_tools"}` y sólo funciona
  con `effort` en `high` o menor (H2).
- Un system contract que use `tool_choice: "any"` o `"tool"` para forzar una tool call se rompe igual en
  Sonnet 5.5 (H2) — la misma ruptura que H2 del informe del 2026-09-24 ya registró para Opus 5.5.
- Un system contract o integración de advisor tool que nombre a Claude Opus 4.8, Opus 4.7 o Claude Sonnet 5
  como advisor deja de funcionar si el modelo que actúa es Sonnet 5.5 (H2).
- Un readiness check o plan de capacidad (paso 10 del flujo) que siga presupuestando Claude Sonnet 4.5 más
  allá del 2026-11-30 queda obsoleto por su retiro programado (H3).
- Un readiness check de logging minimizado (paso 8) que lea `filename` o `title` del Activity Feed de la
  Compliance API para sesiones de Claude for Microsoft 365 deja de recibir esos valores; hace falta resolver
  el nombre por ID con una Compliance Access Key de scope `read:compliance_user_data` (H4).
- Un ejercicio de comparación de proveedores (paso 6 del flujo) que trate a GPT-6 Astra como la única opción
  de OpenAI para código complejo, sin considerar GPT-6.1 Sol a un quinto del precio con rendimiento cercano,
  queda incompleto (H5).
- Un baseline de evals (paso 7) que haya medido comprensión de imágenes de GPT-6 Sol o GPT-6 Luna antes del
  2026-09-25 midió un bug de codificación ya corregido, no la capacidad vigente del modelo (H7): comparar
  esos números contra una corrida posterior al fix no compara lo mismo.
- `learning/sources.yaml:16-17` sigue citando las dos URLs que ya redirigen de forma permanente (H10): es la
  misma clase de práctica obsoleta que H9 acaba de cerrar para `operating-model.md`, todavía sin decidirse
  para estas dos.
