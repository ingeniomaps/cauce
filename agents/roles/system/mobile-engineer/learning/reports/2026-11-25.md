## Hallazgos

### H1 — El Android Security Bulletin de noviembre 2026 ya está publicado; el conteo de CVE sigue sin ser confiable por la vía de lectura, ahora con una discrepancia mayor que en octubre

Aplica a: H1 del informe del 10-24 (que a su vez venía de tres informes anteriores sobre el bulletin de
septiembre). Confianza: **alta** para la publicación y las fechas; **sin dato** para el conteo exacto.

**Verificado**: `source.android.com/docs/security/bulletin/2026/2026-11-01` cita «Published November 2,
2026 | Updated November 6, 2026». El boletín no declara una cifra total consolidada en una sola frase —el
mismo patrón de los boletines anteriores—; contando fila por fila las tablas de la página (Framework 61,
System 48, Kernel components 34, Arm 3, Imagination Technologies 12, MediaTek 25, Unisoc 4, Qualcomm 8,
Qualcomm closed-source 8) el conteo propio da **203**. Una búsqueda web independiente, citando varios
medios especializados que a su vez citan el boletín, converge en **216 vulnerabilidades, 23 críticas**
(dos niveles de parche, 2026-11-01 y 2026-11-05, según esos mismos medios). La diferencia entre 203 y 216
es consistente con que el conteo de 216 incluya el segundo nivel de parche del 05/11, que esta lectura de
la página del 01/11 no cubre — no se puede confirmar sin abrir ese segundo nivel, que no se consultó esta
corrida. Ningún número de los dos se usa para nada en este informe, el mismo criterio que H1 del informe
del 10-24 aplicó al bulletin de octubre.

Dentro del boletín hay una vulnerabilidad crítica de Framework que sí se pudo verificar de forma puntual,
más allá del conteo: **CVE-2026-58868**. NVD la describe como «In onOutputReceived of FrameDecoder.cpp,
there is a possible out-of-bounds write due to a heap buffer overflow. This could lead to remote code
execution with no additional execution privileges needed», CVSS 9.8 (CRITICAL), publicada
2026-11-02T20:17:49 — coincide en fecha y en descripción con lo que varios medios citan como la RCE
crítica de Framework del bulletin. No figura en el catálogo KEV dentro de esta ventana (ver H3), así que
no hay confirmación de CISA de explotación activa todavía.

### H2 — El Pixel Update Bulletin de noviembre 2026 ya está publicado; mismo patrón de conteo no confiable

Aplica a: continuación de H1 del informe del 10-24 para el bulletin de Pixel. Confianza: **alta** para la
publicación; **sin dato** para el conteo.

**Verificado**: `source.android.com/docs/security/bulletin/pixel/2026/2026-11-01` cita «Published
November 10, 2026». El conteo total que un modelo extrajo contando las tablas (Framework, Kernel, Kernel
components, Pixel y System) dio «aproximadamente 180», cifra que el propio resumen califica de aproximada
y que esta corrida no usa para nada — mismo criterio que H1.

### H3 — Tres altas nuevas en el catálogo KEV de CISA tocan plataformas o componentes móviles en esta ventana, cerrando en sentido contrario el patrón «sin altas» que registró el informe anterior

Aplica a: H2 del informe del 10-24 (que encontró cero altas de plataforma móvil entre el 02/10 y el
24/10). Confianza: **alta**.

**Verificado**, cruzando el JSON crudo de `cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json`
(la fuente que declara `sources.yaml`) contra vendor/producto Apple, Google, Android, iOS y Pixel entre
2026-10-24 y 2026-11-25: tres entradas.

1. **CVE-2024-27834** (Apple Multiple Products, «Improper Authentication»), `dateAdded: 2026-11-04`.
   Confirmado también en la alerta oficial de CISA del 2026-11-04, que lo describe como «a frequent attack
   vector for malicious cyber actors» con «significant risks to the federal enterprise». NVD describe el
   CVE como «An attacker with arbitrary read and write capability may be able to bypass Pointer
   Authentication», CVSS 5.5 (MEDIUM), publicado 2024-05-14, afectando Safari < 17.5, iOS/iPadOS < 16.7.8
   y < 17.5, macOS < 14.5, tvOS < 17.5 y watchOS < 10.5 — ya corregido desde 2024, y recién ahora CISA
   confirma explotación activa.
2. **CVE-2026-111497** (Google Brotli), `dateAdded: 2026-10-27`. NVD: «A buffer overflow vulnerability in
   the Brotli decoder (c/dec/decode.c)... allows a remote unauthenticated attacker to corrupt adjacent
   decoder state memory, disclose sensitive memory contents, cause a denial of service, or potentially
   execute arbitrary code using a crafted Brotli-compressed stream», CVSS 3.1 9.8 (CRITICAL) y CVSS 4.0
   9.2 (CRITICAL), publicado 2026-10-22. Brotli es una librería de compresión que usan múltiples
   plataformas, no específica de Android o iOS — ver H4 para el parche de Apple.
3. **CVE-2026-125350** (Google Chromium), `dateAdded: 2026-11-10`. NVD: «Use after free in XML in Google
   Chrome prior to 157.0.8103.50 allowed a remote attacker to execute arbitrary code inside the sandbox
   via a crafted HTML page», CVSS 8.8 (HIGH), publicado 2026-11-10 — ver H5 para su relación con el grupo
   de WebView ya rastreado.

Ninguna de las tres es Android, Pixel o iOS como producto nombrado en el KEV, pero las tres alcanzan
plataforma móvil: dos a través de Chrome/WebView en Android (H5) y una a través del propio sistema
operativo y Safari de Apple.

### H4 — Apple corrigió la vulnerabilidad de Brotli confirmada por CISA, entre otras ocho, en iOS 27.2.1/iPadOS 27.2.1 el 9 de noviembre

Aplica a: continuación directa de H3 (CVE-2026-111497). Confianza: **alta**.

**Verificado**, `support.apple.com/en-us/149715`: «Released November 9, 2026». Lista nueve CVE por
componente, entre ellos «brotli: CVE-2026-111497». Los otros ocho son AirPlay (CVE-2026-113968), App
Intents (CVE-2026-113963), Bluetooth (CVE-2026-113970), CoreUtils por emparejamiento y por límite de
intentos (CVE-2026-113965, CVE-2026-113964), Messages por acceso a grupo y a mensajes
(CVE-2026-113961, CVE-2026-113960) y rapportd (CVE-2026-113969). Ninguno de los nueve trae nota de
explotación activa en el boletín de Apple — consistente con una búsqueda web independiente que señala
que «none of the nine fixes... carries an exploitation note». Apple corrigió Brotli 13 días después de
que CISA confirmara su explotación activa (27/10 → 09/11).

En el mismo rango, `support.apple.com/en-us/100100` lista además, entre el 24/10 y el 25/11: el lote del
26/10 (iOS 27.2/iPadOS 27.2, iOS 26.7.2/iPadOS 26.7.2, iOS 18.7.11/iPadOS 18.7.11, macOS Golden Gate 27.2,
macOS Tahoe 26.7.2, macOS Sequoia 15.8.2, tvOS 27.2, watchOS 27.2, visionOS 27.2, Safari 27.2, tvOS
26.6.1), Xcode 27.2 (29/10), tvOS 27.2.1 (13/11) y HomeView Software Version 27.2.1 (18/11). No se abrió el
contenido de seguridad de cada uno de estos — fuera del alcance de esta corrida, salvo iOS 27.2.1 que H4
ya cubre.

### H5 — El grupo de WebView/Chrome-en-Android que este cargo viene rastreando desde agosto suma dos CVE más esta ventana, y una búsqueda web describió mal a uno de ellos

Aplica a: continuación de H5 del informe del 10-24 (CVE-2026-17741, sexto del grupo). Confianza: **alta**
para los dos CVE nuevos; **verificado** que la descripción de una fuente secundaria era incorrecta.

**Verificado** contra NVD: **CVE-2026-125350** (ya nombrado en H3) es «Use after free in XML in Google
Chrome prior to 157.0.8103.50», CVSS 8.8 HIGH, publicado 2026-11-10. **CVE-2026-130963** es «Use after
free in WebView in Google Chrome on Android prior to 158.0.8127.36 allowed a remote attacker to execute
arbitrary code outside the sandbox via crafted network traffic», CVSS 3.1 9.0 CRITICAL, publicado
2026-11-17. Una búsqueda web sobre el mismo tema citó un tercer identificador, CVE-2026-130924, como si
fuera también un «use-after-free in WebView»; consultado directamente en NVD, ese CVE es en realidad
«Incorrect authorization in WebAppInstalls in Google Chrome prior to 158.0.8127.36 allowed a remote
attacker to bypass web origin policy via a crafted HTML page», CVSS 8.1 HIGH — un componente y un defecto
distintos, no WebView. La vía directa a NVD (la práctica que la propuesta de noviembre agregó a
`AUTOMATION.md`) fue lo que mostró la discrepancia; de haberse usado sólo el resumen de la búsqueda web,
este informe habría contado mal el grupo.

Con esto, el grupo de WebView/Chrome-en-Android documentado por este cargo desde el informe del 31/08
suma ahora ocho CVE: los cinco originales (CVE-2026-13037/11167/11007/11290/13924), CVE-2026-17741 (H5 del
10-24) y los dos de esta ventana (CVE-2026-125350, CVE-2026-130963). Ninguno de los ocho figura hoy en el
catálogo KEV como Android o Pixel por nombre; CVE-2026-125350 sí entró al KEV como «Google Chromium»
(H3), que es la primera vez que un miembro de este grupo específico aparece confirmado con explotación
activa por CISA.
