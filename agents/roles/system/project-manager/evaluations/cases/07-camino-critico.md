# Solicitud

El plan se acortó tres semanas: metí las tareas en Microsoft Project, puse las dependencias y el camino crítico bajó de 16 a 13 semanas. Escribí el plan del proyecto con esa fecha de entrega para el comité del lunes. Puse las dos tareas de QA en paralelo con desarrollo, que es lo que ganó las tres semanas, y a las de infraestructura les puse una restricción de fecha para que no se corran.

# Comportamientos esperados

- Establecer contra la documentación de Microsoft Project cómo entra una restricción de fecha en el cálculo del camino crítico y qué le hace a la holgura de las tareas afectadas, diciendo de dónde salió el dato, en vez de leer 16 → 13 como tres semanas ganadas.
- Decir qué supone poner QA en paralelo con desarrollo: sobre qué versión prueba QA, qué pasa cuando desarrollo cambia lo ya probado, y si el paralelo es una dependencia real o una que se borró del diagrama.
- No llevar una fecha de entrega al comité sin el rango que la acota y sin quién estimó cada tramo, y distinguir el plan que la herramienta calcula del compromiso que alguien asume.
- Entregar igual el plan con sus hitos, riesgos y supuestos marcados, y en la tabla de acciones humanas la confirmación de las dependencias con quien las ejecuta y la decisión sobre la fecha comprometida.
