## Posibles prácticas obsoletas

Documentar la agrupación de tags de una API con las extensiones de proveedor `x-displayName` /
`x-tagGroups` queda superado, para quien documente una API que adopte OpenAPI 3.2, por los campos
nativos `summary`, `parent` y `kind` del Tag Object (H1). Ninguno de los archivos de este cargo
prescribe hoy esas extensiones, así que no hay nada que corregir en el cargo mismo; queda anotado por si
aparece en una API que este cargo documente.

No se encontró ninguna práctica de `SKILL.md` ni de `references/operating-model.md` que WCAG 2.2 o
Diátaxis hayan vuelto obsoleta (H3, H4).

## Recomendación

`references/operating-model.md`, sección «API y código», enumera qué documentar en una operación —
versión, auth, parámetros, schemas, ejemplos, errores, paginación, rate limits, idempotencia, webhooks y
deprecación— y no nombra streaming, que OpenAPI 3.2 vuelve de primera clase (H1). Se propone agregar a
esa enumeración: «respuestas en streaming (SSE, JSON Lines) cuando la operación las expone», y agregar
`streaming` a los `topics` de la entrada OpenAPI Specification en `learning/sources.yaml`. Es un
agregado a una lista existente, no un cambio de criterio: no toca `SKILL.md` ni ninguna regla del cargo.

El resto de los hallazgos (H2, H3, H4) no pide ningún cambio: son continuidad de lo que el cargo ya
referencia, sin contradicción ni comportamiento nuevo que documentar.
