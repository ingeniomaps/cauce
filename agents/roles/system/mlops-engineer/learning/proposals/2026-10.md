## Riesgos y regresiones

**Tensión con `require_corroboration_for_major_change: true`.** Agregar tres fuentes a la vez podría
leerse como un cambio mayor sin la corroboración que la regla exige. Se resuelve así: las tres están
corroboradas por evidencia de **cinco** corridas consecutivas (2026-08-31 a 2026-09-24), cada una
repitiendo o reforzando la misma recomendación sin que ninguna corrida posterior la contradijera —es
exactamente el patrón de corroboración que la regla pide, no una fuente aislada de una sola corrida.

**Tensión con `reject_unsourced_claims` dentro de las propias notas de uso.** Las notas no afirman un
comportamiento garantizado de MLflow o de GitHub Advisory («siempre tarda una semana», «el campo nunca se
actualiza»): afirman el hecho verificado y puntual (fechas, PR, CVE citados arriba) y marcan la
consecuencia operativa como práctica a aplicar hacia adelante, no como ley del proveedor — mismo
registro que usa cada informe fuente (H1 2026-09-24 es explícito: «hipótesis: no se puede establecer sin
releer cada fuente si algún dato de corridas anteriores arrastra el mismo tipo de error»). No hay
afirmación de mecanismo sin su registro entre las que se agregan.

**Riesgo de ruido en el ciclo de investigación (R20).** Tres fuentes nuevas de tier `project`/`advisory`
amplían lo que cada corrida mensual tiene que releer. Mitigado porque las tres son acotadas —dos páginas
de advisories y un feed JSON, no un barrido abierto— y la cadencia no cambia (siguen siendo mensuales);
el costo ya lo pagaron las cinco corridas que las propusieron, agregarlas no lo repite.

**Casos adversariales de `evaluations/cases/` — ninguno queda expuesto a una regresión por este cambio.**
El cambio no toca `SKILL.md` ni `evaluations/expected-behaviors.yaml`: ningún comportamiento esperado o
prohibido cambia de contenido, sólo se ampliaron las fuentes que alimentan el ciclo de aprendizaje de
este cargo (`learning/`), que es un árbol distinto del que los siete casos ejercitan (operación de un
