### H3 — Dos advisories nuevas, publicadas 2026-09-23 y nunca vistas por este cargo hasta hoy: una sin parche todavía (dspy), la otra ya resuelta desde 3.15.0 (statsmodel)

Confianza: **alta** para los hechos verificados por separado; **hipótesis** para si `GHSA-2qmw-5xhm-qq5w`
y `GHSA-gqvg-gmmx-x4hm` son la misma vulnerabilidad con un CVE asignado después.

Verificado, página propia de `GHSA-q5f3-5gj6-hmj7` (fuente 19, cita textual verbatim): *"MLflow's dspy
flavor, versions >= 2.0, applies the MLFLOW_ALLOW_PICKLE_DESERIALIZATION=False security control only when
the model_path ends in .pkl, which allows a remote attacker to execute arbitrary code via a crafted
MLmodel artifact."* CVE asignado: `CVE-2026-96775`. CVSS 8.8. Publicada 2026-09-23. Sin versión parcheada
declarada en la propia página. Verificado directo en el código fuente de `master` (fuente 31): la función
de carga de `dspy` sigue condicionando el control de pickle a que la ruta termine en `.pkl` — el mecanismo
que describe la advisory sigue presente hoy, sin parche.

Verificado, página propia de `GHSA-2qmw-5xhm-qq5w` (fuente 20, cita textual verbatim): *"MLflow's
statsmodel flavor, versions 2.1.0 to 3.14.0, omits the MLFLOW_ALLOW_PICKLE_DESERIALIZATION=False security
control entirely in _load_model(), which allows a remote attacker to execute arbitrary code via a crafted
MLmodel artifact."* CVE asignado: `CVE-2026-96804`. CVSS 8.8. Publicada 2026-09-23.

Hipótesis: `GHSA-2qmw-5xhm-qq5w` describe el mismo mecanismo, el mismo paquete, el mismo rango de
versiones afectadas y el mismo flavor que `GHSA-gqvg-gmmx-x4hm` (fuente 24: sin CVE en su propia página,

## Posibles prácticas obsoletas

**Nueva esta corrida, la más importante: tratar el primer resultado o la primera página de una búsqueda
por texto libre como si fuera la lista completa.** H2 muestra que `github.com/advisories?query=mlflow`
devuelve 91 resultados en 4 páginas, y que tres advisories del propio paquete `mlflow` —ya conocidas por
este cargo desde antes de que existiera la fuente global— aparecen recién en la última página, no en la
primera. Si esta corrida se hubiera quedado con la primera página (lo que la nota de uso actual de
`sources.yaml` no dice que haya que evitar), habría repetido para `mlflow` el mismo problema que la fuente
reemplaza para `mlflow.org/releases`: una fuente que sí tiene el dato, leída de una forma que no lo
muestra. Acotar la búsqueda con `type:reviewed ecosystem:pip` reduce el ruido (91 a 84, mejor orden) pero
no lo elimina —sigue trayendo una advisory de GitPython en el puesto 15— ni garantiza que las tres
advisories de la página 4 aparezcan en la primera página acotada. Para este cargo, la consecuencia es que
la fuente recién aprobada necesita una nota de uso sobre cómo leerla, no sólo la URL. Ver «Recomendación».

**Nueva esta corrida: una página que empareja varias entidades relacionadas —dos CVE con dos componentes,
en este caso— es más propensa a que el resumen automático las cruce mal que una página dedicada a una sola
entidad.** H4 es un segundo caso del mecanismo que ya señalaba H8 del 2026-09-24 (una fecha mal
transcripta desde una página HTML), ahora sobre un emparejamiento ID↔atributo en vez de una fecha. La
consecuencia operativa es la misma que ya recomendaba H8: para un dato que vincula dos identificadores
entre sí, preferir la página dedicada a cada identificador por separado (como las fuentes 19 y 20) antes
que una página que los trata juntos (como la fuente 25), y si sólo hay una fuente que los trata juntos,
cruzarla contra al menos una fuente de terceros independiente antes de usarla para una recomendación.

**Reforzada esta corrida: el campo «Patched versions»/«First Patched Version» de una advisory sigue sin
ser el techo de lo que esa vulnerabilidad necesita.** H5 es el mismo caso (`CVE-2026-2635`) que ya
señalaban el 2026-09-21 y el 2026-09-24, sin cambio esta vez — se repite el registro porque sigue siendo
cierto, no porque haya evidencia nueva.

**Nueva esta corrida, operativa y no de contenido: cuando la API JSON de `api.github.com` devuelve 403 a
mitad de una investigación, probar la página HTML equivalente antes de registrar el dato como no
disponible.** H9 es la primera vez que este cargo documenta haber chocado con esto; la página HTML
(fuentes 19, 20, 24) dio exactamente el mismo dato que la API JSON hubiera dado, así que no fue necesario
abandonar ninguna de las comprobaciones de esta corrida por el 403.

Se mantienen, sin cambio, las prácticas ya señaladas en corridas anteriores: «leer 'tiene basic-auth
habilitado' como 'acceso mínimo' sin mirar versión» (2026-08-31 en adelante), «no fijar la lectura del
`CHANGELOG.md` a un tag de release específico» (2026-09-14 en adelante), y «no tratar 'Patched
versions'/'First Patched Version' como definitivo sin revisar los PR que la propia advisory referencia y
el cuerpo del release» (2026-09-21 en adelante).

y por `unverified_tool_or_engine_behavior_asserted_as_fact` (ver «Evaluación» más abajo).

`sources.yaml`**, a partir de H2: no quedarse con la primera página de
`github.com/advisories?query=mlflow`; revisar al menos las páginas siguientes hasta confirmar que los
