### H2 — Node.js: nueva security release con una CVE alta de RCE que afecta la línea 24.x; el entorno de esta corrida está por debajo del parche

- **Estado**: hallazgo nuevo — primera novedad de fondo en siete informes. El H2 de los seis informes
  anteriores («sin security release desde el 2026-07-29») queda superado.
- **Verificado hoy**: Node.js publicó una security release el **2026-10-21**, con **10 CVE** (4 altas, 3
  medias, 3 bajas), para las líneas 26.x, 24.x y 22.x. La de mayor severidad y la única con ejecución remota
  de código es **CVE-2026-111497** («Node2Shell»): el decodificador Brotli embebido en `node:zlib` escribe
  fuera de un buffer interno de ocho bytes con una entrada mal formada, lo que puede corromper memoria del
  proceso y llevar a caída, filtración de memoria o ejecución de código. Afecta **26.x, 24.x y 22.x**;
  parchea en **v26.12.1, v24.22.1 y v22.23.4** respectivamente. Fuente primaria leída entera
  (`nodejs.org/en/blog/vulnerability/october-2026-security-releases`); corroborado con nueve notas de prensa
  de seguridad independientes (`WebSearch`), que coinciden en CVE, versiones y parche sin contradecirse.
  Las otras tres CVE altas son *bypass* de verificación de hostname TLS (dígitos de ancho completo,
  direcciones IPv4 no canónicas con cero inicial) y un truncamiento de nombre por byte NUL en `dns.resolve*`
  — las tres de 24.x también.
- **Verificado hoy, por lectura del propio código**: `engine/` y `automatization/` no tienen ningún
  `require`/`import` de `node:zlib`, `node:tls`, `node:https` ni `node:dns`, ni ningún `fetch(` — búsqueda
  literal sobre los dos directorios. El motor de Cauce no llama directamente a ninguno de los módulos que
  esta release corrige: lo de red lo hace siempre invocando `gh`, `npm` y `git` como binarios externos, no
  con los módulos de Node.
- **Local, dado por el job y no comprobado con un comando propio esta corrida**: el entorno es **Node
  v24.21.0** — por debajo de la versión parcheada (v24.22.1), publicada tres días antes de esta corrida.
  `ci.yml`, `agent-learning.yml`, `release.yml`, `release-pr.yml` y `open-pr.yml` fijan `actions/setup-node`
  con `node-version: '24'` (flotante dentro de la major), que en principio resuelve a la última 24.x
  disponible en cada corrida — pero esta corrida en particular trae una versión de tres días más vieja que
  el parche, y no hay cómo establecer desde acá si es la imagen del runner la que todavía no se actualizó o
  si es otra cosa.
- **Lo que esto no establece**: si algo en el pipeline de CI o de este propio ciclo de aprendizaje llega a
  decodificar contenido Brotli no confiable con el `node:zlib` de este binario —por ejemplo, dentro de
  `npm install`/`npm publish`, que sí hacen peticiones de red sobre este mismo proceso de Node vía su
  `undici` interno—. No se comprobó si el registro de npm responde con `Content-Encoding: br` a estas
  llamadas ni si `npm` en esta versión usa el decodificador vulnerable para leerlas; queda como pregunta
  abierta 4.
- **Por qué importa para este contrato**: `engines.node` sigue en `">=24"` sin piso de parche —la práctica
  obsoleta que los seis informes anteriores vienen señalando como riesgo genérico— y ahora hay una CVE alta
  concreta, con RCE, por debajo de ese piso abierto. Deja de ser sólo una preocupación de higiene y pasa a
  ser una versión vulnerable conocida que el manifiesto del propio paquete no excluye.
- **Confianza**: **alta**, verificado en fuente primaria y corroborado en nueve fuentes independientes, para
  la CVE y sus versiones; **alta** en que el motor propio no llama a los módulos afectados; **media-baja**
  en la exposición real de la corrida de CI/publicación, que no se comprobó.
