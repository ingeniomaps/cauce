### H8 — GitHub Changelog: tres entradas de seguridad/pipeline en la ventana; una toca directamente la cuenta de npm que este mismo repositorio usa para publicar

Confianza: **alta** para el listado (**verificado**); **documentado** para el contenido detallado de

De las entradas del 2026-09-07 al 2026-09-14 (predominantemente Copilot/enterprise, sin relevancia
directa para riesgos u oráculos de QA), tres tocan seguridad de pipeline o de la cadena de suministro:

- **«Block pull requests with exposed secrets from merging»** (2026-09-09, público en preview para
  clientes de GitHub Secret Protection o Advanced Security): agrega una regla de ruleset que exige que
  un escaneo de secretos haya corrido sobre el commit de cabeza y que no haya alertas abiertas antes de
  mergear — una compuerta adicional a la que ya existe en el push, pensada para patrones genéricos que
  el push protection puede tener deshabilitados.
- **«npm extends recovery-code security holds to all accounts»** (2026-09-09): el *hold* temporal de
  72 horas tras un inicio de sesión con código de recuperación, antes limitado a cuentas de «alto
  impacto», ahora aplica a **cualquier cuenta**. Durante el hold se pausan publicaciones y la creación
  de tokens de acceso; instalar paquetes sigue funcionando. Es aditivo respecto del flujo OIDC de
  *trusted publishing* que `AGENTS.md` describe para `release.yml` de este repositorio — no lo rompe —,
  pero si alguna vez se usa un código de recuperación sobre la cuenta que sostiene el `NPM_TOKEN` de
  respaldo, hay 72 horas en las que ese respaldo no puede publicar.
- **«Control GitHub Actions cache access with cache-mode»** (2026-09-10, disponibilidad general): permite
  fijar acceso de mínimo privilegio (`read`, `write`, `write-only`, `none`) a la caché de Actions por
  workflow o por job, para mitigar ataques de *cache poisoning* sobre workflows con permisos elevados.

No es un hallazgo de la profesión de QA — es contexto operativo de release/DevOps/seguridad de la
cadena de suministro — y se registra acá, igual que H7 del informe del 2026-09-07, porque una de las
tres entradas toca directamente un mecanismo que este mismo repositorio declara usar (`AGENTS.md`,
sección de publicación por tag y OIDC).

   elevados; no es un default nuevo, es una opción que conviene adoptar donde el workflow maneja
   permisos sensibles.
3. Ningún ítem de esta corrida reabre los de las listas de los informes anteriores (2026-08-31,
   2026-09-07): siguen valiendo sin cambios.
