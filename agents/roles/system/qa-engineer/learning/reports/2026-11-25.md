### H2 — Playwright 1.65.0 trae varios *breaking changes* que tocan oráculos de aserción, y 1.65.1 corrige una regresión que el propio 1.65.0 introdujo

Aplica a: Playwright. Confianza: **alta** (**documentado**, notas de release oficiales de GitHub).

De los *breaking changes* declarados en 1.65.0, tres cambian directamente qué hace pasar o fallar una
prueba:

- **Actionability**: las acciones de un locator (`click`, `check`, `fill`, …) ahora esperan a que el
  elemento no sea *inert*, y hacen timeout si lo es. Una acción que antes procedía sobre un elemento
  marcado `inert` ahora puede quedar colgada hasta el timeout.
- **Cookies RFC 6265**: las cookies *host-only* dejan de matchear subdominios, y el matching de `path`
  es más estricto. Una aserción sobre qué cookies ve el navegador puede cambiar de resultado sin que
  nadie haya tocado la página bajo prueba.
- **Credenciales de proxy**: ya no se envían al sitio web — hay que usar `httpCredentials` para
  autenticación del sitio. Un test que dependía de que el proxy autenticara también al sitio deja de
  pasar.

Un cuarto rompe algo adyacente y no una aserción: las corridas *sharded* ahora fallan con «No tests
found» cuando ningún shard matchea tests (antes pasaban vacías); se evita con `--pass-with-no-tests`.

Y 1.65.1, publicada ocho días después, es enteramente la corrección de una regresión que 1.65.0 causó:
**«Regression: decorated class with a static field fails to load in 1.65 ('_initClass is not a
function') with useDefineForClassFields: false»** — el propio cambio de semántica de class fields que
1.65.0 declaró como breaking (seguir `useDefineForClassFields` de `tsconfig.json`) rompió un caso que la
propia release no había cubierto. Es un dato relevante para cualquiera que mida «¿alcanza con leer las
notas de la versión X, o hay que esperar al primer patch?» — no se afirma una respuesta general, sólo se
registra el caso concreto.

Como en el informe anterior con la 1.64: el contrato de este cargo es agnóstico de herramienta y no cita
semántica de Playwright, así que no hay nada que tocar en `SKILL.md`. Se registra para quien mantenga
una suite de Playwright y revise este informe. Playwright 1.65.0 también deja de soportar Node.js 20
(requiere 22, 24 o 26); este repositorio ya corre sobre 24/`current` (H7), sin impacto acá.

### H3 — Cypress publicó dos avisos de seguridad de severidad alta; ambos sólo alcanzan a `cypress open`, no a `cypress run` ni a CI

Aplica a: Cypress. Confianza: **alta** (**documentado**, dos GitHub Security Advisories oficiales del
propio repositorio, corroboradas entre sí y con una búsqueda web general).

**GHSA-pgrh-36vg-cqj7** (CVSS 3.1: **8.8**, alta): en modo *open*, el servidor GraphQL de Launchpad
escuchaba en todas las interfaces de red (no sólo loopback) y su endpoint HTTP no validaba el origen de
las peticiones entrantes. Afecta 10.0.0–15.21.1 y 16.0.0–16.2.x; parcheado en **15.21.2** y **16.3.0**.

**GHSA-x3c4-839h-qv4x** (CVSS 3.1: **7.5**, alta; vector `AV:N/AC:H/PR:N/UI:R/S:U/C:H/I:H/A:H`): los
endpoints WebSocket del test runner, bajo `/__socket`, aceptaban conexiones de cualquier origen mientras
Chrome, Chromium o Edge estaban abiertos para testing. Afecta 15.21.0–15.21.1 y 16.0.0–16.2.1; parcheado
en las mismas dos versiones.

En los dos casos, un dispositivo en la misma red o un sitio web malicioso/comprometido podía ejecutar
comandos arbitrarios con los privilegios de quien corre Cypress. El propio aviso acota el alcance: sólo
`cypress open` arranca los servidores vulnerables; `cypress run` y los entornos de CI no los inician y no
quedan expuestos.

No hay nada que tocar en `SKILL.md` ni en `sources.yaml` por esto —Cypress no es una fuente formal del
cargo, igual que Playwright o Selenium— y, como el bugfix de seguridad de Cypress del informe anterior,
es higiene de la propia herramienta y no un cambio de oráculo. Pero la severidad (ejecución arbitraria de
comandos, no una fuga de datos) y que el vector sea «tener la herramienta de testing abierta en modo
interactivo» la distinguen de una dependencia transitiva corregida de paso: se registra en «Posibles
prácticas obsoletas» para quien use Cypress en modo *open* sobre una red compartida.

### H4 — pytest 9.2.0 trae varios *breaking changes*, incluida una reclasificación de los exit codes de un fallo de import de plugin

Aplica a: pytest. Confianza: **alta** (**documentado**, changelog oficial).

Tres cambios rompen compatibilidad:

- `pytest.mark.parametrize`: los parámetros `indirect`, `ids` y `scope` pasan a ser **sólo por
  nombre** (`keyword-only`); una llamada que los pasaba posicionalmente deja de poder coleccionarse.
- La opción `-c` ahora falla si la ruta no existe, es un directorio, o tiene un formato no soportado;
  antes esos casos se ignoraban en silencio.
- Un fallo de import de plugin pasa de un exit code genérico (**1**) a dos códigos distintos:
  `USAGE_ERROR` (**4**) para un plugin faltante e `INTERNAL_ERROR` (**3**) para un import roto.

El tercero es el que más directamente toca el método de este cargo: un script de CI que interpreta
«exit code 1 → hay tests que fallaron» sobre una corrida con un plugin roto, con pytest 9.2.0 ya no ve
ese 1 — ve un 3 o un 4, que no es la semántica que el script asumía. No es un caso que el contrato de
`SKILL.md` cite (es agnóstico de herramienta, igual que con Playwright y Selenium), pero es exactamente
la clase de cosa que `AUTOMATION.md` pide priorizar («cambios de plataforma que alteren … oráculos») si
alguna instalación tiene ese script.

Deprecaciones declaradas, sin remoción todavía: `CallSpec2` renombrada a `CallSpec` (alias viejo
disponible, remoción en pytest 10 u 11); `yield_fixture` programado para remoción; fixtures de alcance
alto definidas como método de instancia; valores no-string en opciones INI tipadas string, con warning.

## Posibles prácticas obsoletas

1. **Configurar `deps.optimizer.web` en Vitest.** Sigue deprecada desde 5.0.1 (informe 2026-09-21, H3);
   sin cambio en 5.1.0 ni 5.1.1.
2. **Depender de que `--update-snapshots=missing` falle cuando falta un snapshot, en Playwright.**
   Vigente desde 1.64.0 (informe anterior, H2); sin cambio en 1.65.x.
3. **Aserciones de visibilidad que asumen que un elemento dentro de un iframe oculto puede seguir
   reportándose visible por su propia visibilidad local, en Playwright.** Vigente desde 1.64.0 (informe
   anterior, H2); sin cambio en 1.65.x.
4. **Acciones de Playwright sobre un elemento marcado `inert` que antes procedían igual.** Nueva esta
   corrida (H2): desde 1.65.0, `click`, `check`, `fill` y el resto esperan a que el elemento deje de ser
   `inert`, y hacen timeout si no lo hace.
5. **Depender de que las credenciales de un proxy de Playwright autentiquen también al sitio web.**
   Nueva esta corrida (H2): desde 1.65.0 ya no se envían al sitio; usar `httpCredentials` para eso.
6. **Pasar `indirect`, `ids` o `scope` de forma posicional a `pytest.mark.parametrize`.** Nueva esta
   corrida (H4): desde pytest 9.2.0, los tres son sólo por nombre y una llamada posicional deja de
   coleccionarse.
7. **Un script de CI que interpreta el exit code 1 de pytest como «hay tests que fallaron» sin
   distinguir un fallo de import de plugin.** Nueva esta corrida (H4): desde pytest 9.2.0 ese caso usa
   los códigos 3 o 4, no el 1.
8. **Ejecutar `cypress open` en una red compartida o no confiable con una versión anterior a 15.21.2 o
   16.3.0.** Nueva esta corrida (H3): dos vulnerabilidades de severidad alta permiten ejecución arbitraria
   de comandos contra quien tiene la herramienta abierta en modo interactivo. No afecta `cypress run` ni
   CI.
9. **Depender de `driver.webextension` en el binding Python de Selenium.** Nueva esta corrida (H1):
   deprecado en 4.53.0, sin fecha de remoción declarada en la nota de release.
10. Las de los informes anteriores (Selenium Grid, `cache-mode` de GitHub Actions) siguen valiendo sin
    cambios; ver el informe del 2026-09-14 para el detalle.
