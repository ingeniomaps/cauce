## Hallazgos

### H1 — dbt-core 1.12.4 corrige un defecto real: los tests genéricos quedaban indefinidos tras cargar un manifiesto generado por Fusion

Confianza: **alta**. [Verificado] (dos lecturas independientes de la misma fuente, mismo contenido) API
de releases de GitHub: `dbt-labs/dbt-core`, `tag_name: "v1.12.4"`, `published_at: "2026-09-08T10:00:57Z"`.
El cuerpo del release, citado literalmente en ambas lecturas: «Re-parse the built-in generic tests
(test_not_null, test_unique, test_accepted_values, test_relationships) after loading a Fusion-generated
manifest, so they are not permanently evicted and left undefined at test-compile time.» Es decir: antes de
este fix, un proyecto que compilaba con un manifiesto generado por Fusion y luego corría con dbt-core podía
quedarse sin sus tests genéricos incorporados sin ningún error — quedaban «permanently evicted and left
undefined». Toca directo «Tests y reconciliación» del contrato de modelo de este cargo: es exactamente el
tipo de falla silenciosa (un test que debía correr y no corrió, sin aviso) que esa sección pide cubrir con
tests estructurales y reconciliación independiente. El mismo release corrige además que `target/
manifest.json` no reflejaba las macros de adaptador realmente usadas para compilar tras cargar un
manifiesto de Fusion, y valida que una ruta de instalación de paquete no pueda resolver fuera del
directorio configurado. Ninguno de los tres es un cambio incompatible declarado; los tres son correcciones
de defectos en la convivencia dbt-core/Fusion que el informe del 2026-08-31 (H1) ya identificaba como zona
activa de cambio.

Nota de método: la página `/releases` de GitHub para este repositorio, leída sin filtrar por «latest»,
mostró como ítem superior un prerelease de prueba (`v2.0.0-dev.39-test-pypi`, 2026-09-09) en vez de la
última versión estable. El endpoint `/releases/latest` de la API sí excluye prereleases y drafts, y es la
fuente que sostiene este hallazgo. Vale para corridas futuras: la vista humana de `/releases` no basta
para identificar «la última estable» de este repositorio.

hallazgo de esta semana introduce una conducta nueva a exigir o prohibir en `SKILL.md` ni en
`evaluations/expected-behaviors.yaml`.
