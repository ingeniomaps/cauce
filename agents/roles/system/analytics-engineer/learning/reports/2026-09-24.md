## Posibles prácticas obsoletas

- **Registrar el bloqueo de `iso.org` como un hecho único e indivisible.** H1 muestra que el bloqueo no es
  parejo por dominio: `webstore.iec.ch` y `committee.iso.org` respondieron hoy sin error, mientras
  `www.iso.org` sigue en `403`. Las próximas corridas deberían registrar el subdominio consultado junto con
  el resultado, no «iso.org» como bloque, para no perder la señal de que parte del acceso ya se recuperó.
- **Usar la API JSON de PyPI como fuente de fecha de publicación sin corroborar.** H4 muestra un caso
  concreto donde esa API devolvió una fecha (`2024-12-19`) que dos fuentes independientes (la página HTML
  de otra corrida y una búsqueda web de esta) contradicen con `2026-09-16`. Para el número de versión la
  API fue consistente con lo ya registrado; para la fecha, no. Vale la pena preferir la página HTML o una
  búsqueda de corroboración para fechas de PyPI, y usar la API sólo para el número de versión.
- Se reafirman, sin novedad, las tres prácticas ya registradas en el informe del 2026-09-21 (trackear
  `dbt-labs/dbt` en vez de `dbt-labs/dbt-fusion`; no confiar en `/releases` de GitHub para `dbt-snowflake`;
  la entrada pendiente de `sources.yaml`/`operating-model.md` sobre dbt v2). No se repiten en detalle acá.
- **La recomendación pendiente sobre la fecha del charter del Dataset Exchange Working Group (H3 del
  2026-08-31) sigue sin aplicarse, ahora en su quinto informe.** `learning/HISTORY.md` sigue vacío (sólo el
  encabezado) y `learning/proposals/2026-09.md` sigue `status: archived` con `automatic_apply: false`; ni
  `sources.yaml` ni `operating-model.md` muestran la anotación. Se re-registra por quinta vez.
