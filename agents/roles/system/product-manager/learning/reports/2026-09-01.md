**H2 — Una fuente reconsultada (MetaGPT releases) devolvió primero una fecha equivocada por un año, y
sólo una segunda consulta por otro medio la corrigió (hecho, verificado; nota de método).** El primer
fetch de `https://github.com/FoundationAgents/MetaGPT/releases` resumió las últimas releases como
`v0.8.2 — March 9, 2024`, `v0.8.1 — April 22, 2024`, `v0.8.0 — March 29, 2024`. Eso contradice
directamente el H5 del informe anterior (2026-08-31), que registró esas mismas releases como de
marzo–abril de **2025** citando la misma URL. Antes de escribir cualquier hallazgo sobre esto se hizo
una segunda consulta independiente — búsqueda web con la consulta "FoundationAgents MetaGPT v0.8.2
release github tag date" — que devolvió: "MetaGPT v0.8.2 was released on March 9, 2025 at 15:59. The
commit date associated with the tag is March 2, 2025", con la página de releases y la del tag `v0.8.0`
como fuentes. La página del tag `v0.8.2` por sí sola tampoco alcanzó: mostró "released this 09 Mar
15:59" sin año. El año correcto es **2025**, no 2024; el fetch de esta corrida se descarta como
erróneo. No cambia la conclusión de fondo (MetaGPT sigue sin actividad nueva, consistente con H5 del
informe anterior), pero sí es evidencia de que un único fetch de fecha —sobre todo de año— no alcanza
como registro `verificado` cuando dos consultas a la misma fuente en el mismo día ya discreparon entre
sí; hace falta una segunda vía antes de citarlo.

job sólo tiene un commit y es de esa fecha". Dato de entorno de esta corrida, dado por el job y no
