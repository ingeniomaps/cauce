## Hallazgos

### H1 — scikit-learn: nueva release 1.9.1 (2026-09-10), incluye un fix que cambia el resultado numérico de LDA/QDA con `solver="svd"`

Confianza: **alta**.

La API JSON de PyPI del paquete (verificado) pasó de dar `1.9.0` (registrado en los tres informes
anteriores) a dar `info.version: "1.9.1"`. La API JSON de la release puntual (verificado) da
`upload_time_iso_8601: "2026-09-10T18:32:29.891551Z"` para el primer archivo publicado. El changelog de la
serie 1.9 (verificado, cita literal de `scikit-learn.org/stable/whats_new/v1.9.html`) lista, entre otros
fixes, uno sobre `discriminant_analysis.LinearDiscriminantAnalysis` y
`discriminant_analysis.QuadraticDiscriminantAnalysis`: *"the normalization for `solver=\"svd\"` is changed
to `1/n_samples` instead of `1/(n_samples - n_classes)` and `1/(n_samples - 1)`, respectively, which is
consistent with the maximum likelihood covariance estimator (same as the `solver=\"eigen\"` default)"*
(PR #33626). El resto de los cambios listados son fixes de metadata routing, callbacks, `cluster`,
`datasets`, `neighbors`, `preprocessing`, `svm` y `utils` sin efecto en el resultado numérico de un
modelo entrenado.

Impacto ML: a diferencia de los cambios de PyTorch/scikit-learn registrados en informes anteriores (build,
C++, distribuido, deprecaciones de API), éste cambia el **valor numérico** que devuelve un estimador ya
entrenado con la misma configuración, sin cambiar la firma ni requerir código nuevo — el tipo de cambio que
`operating-model.md` cubre bajo "código/commit, configuración, seed, entorno, **dependencias**" del
contrato de experimento reproducible, y que `SKILL.md` ya pide versionar. No hay nada que agregar a esa
regla: el hallazgo es un caso concreto que la sostiene, no una laguna. No hay caso de evaluación de este
cargo que dependa de un resultado numérico de LDA/QDA con `solver="svd"`, así que no hay evidencia de
regresión propia que corregir.
