## Hallazgos

### H1 — PyTorch: nueva release 2.14.0 (2026-09-02); el resumen automático de la página HTML de la release volvió a errar el año, tercera vez que se observa el mismo patrón

Confianza: **alta** para versión y fecha (contrastadas por dos vías independientes); **alta** para el
contenido de los cambios incompatibles, tomados de las notas de la release; **hipótesis** cualquier lectura
de por qué el resumen automático repite este error.

La API de releases de GitHub (verificado, JSON crudo) da `tag_name: "v2.14.0"`, `published_at`
**2026-09-02T17:40:10Z**. El resumen automático de la página HTML de esa misma release (verificado,
`github.com/pytorch/pytorch/releases/tag/v2.14.0`) devolvió **«Release Date: September 2, 2024»** — mismo
día y mes, año equivocado. Es el mismo tipo de error que ya documentó `qa-engineer` el 2026-08-29 y que este
cargo documentó como H4 el 2026-08-31 (esa vez sobre la release 2.13.0, vía la página índice de releases en
vez de la página de una release puntual): tercera observación del mismo patrón, ahora también sobre la
página de una release individual y no sólo sobre el índice. Sigue sin haber contraste suficiente para
afirmar la causa (¿caché del resumen?, ¿la propia página HTML muestra mal el año?): eso queda en hipótesis,
no en hallazgo.

Cambios incompatibles listados en las notas de la release (verificado, cita cercana de la propia página):
remoción de la política de acumulación `"balanced"` en cross entropy lineal (usar `"compact"`); los
subgradientes de clamp/min/max en los límites no diferenciables ahora siguen el espacio de entrada del
esquema del dispatcher; los grupos de proceso custom en Python deben aceptar `backend` como keyword en
`new_group()`; los segmentos de memoria simétrica NCCL asignados tarde ya no se auto-promueven a ventanas
simétricas tras `register_mem_pool(..., symm=True)`; `torch.distributed.split_group()` devuelve
`GroupMember.NON_GROUP_MEMBER` en vez de `None` para ranks no miembros; remoción definitiva de
`torch.cholesky()`/`Tensor.cholesky()`/`torch.qr()`/`Tensor.qr()` (usar `torch.linalg`); remoción de
`use_cuda` en los profilers de `torch.profiler`/`torch.autograd.profiler`; remoción del backend TVM relay
legado; cambios en overloads C++ de `c10::Scalar::isIntegral()`; `setup.py` pasa a ser un shim que redirige a
comandos nuevos hasta 2.15, y deja de funcionar en 2.16; renombre de `at::mps::is_macos_13_or_newer()` a
`at::mps::is_macos_at_least()`; y la promoción de tipos complejos con `bfloat16` cambia de `torch.complex64`
a `torch.bcomplex32`.

Impacto ML: como con 2.13.0 en el informe anterior, ninguno de estos cambios toca las prácticas que
`SKILL.md`/`operating-model.md` de este cargo nombran (splits, leakage, métricas, evaluación GenAI). Son de
build, C++, distribuido, MPS y álgebra lineal de bajo nivel — el único con alguna cercanía a evaluación es la
remoción de `torch.qr()`/`torch.cholesky()` en favor de `torch.linalg`, que es un cambio de API de PyTorch,
no de práctica de evaluación de modelos.
