## Las dos afirmaciones, refutadas

**1. «`terraform plan` en verde garantiza que el `apply` no destruye nada» — falsa.**
*Verificado* — Terraform v1.15.8 (linux_amd64), `terraform plan -help` y `terraform apply -help`, ambos exit 0, hoy en esta máquina. Falla por tres razones independientes:

- El plan **enumera** las destrucciones, no las excluye. Literal: «Generates a speculative execution plan, showing what actions Terraform would take». Un plan con doce destrucciones adentro termina en verde: mostrarlas es su trabajo. Tanto que destruir es un modo de planificación propio (`-destroy`), y ese plan también sale verde.
- «Verde» ni siquiera significa «sin cambios». Literal de `-detailed-exitcode`: «0 - Succeeded, diff is empty (no changes) / 1 - Errored / 2 - Succeeded, there is a diff». Sin esa opción, exit 0 sólo dice que el comando no explotó.
- Plan y apply no son la misma operación salvo que se pase el archivo. Literal de apply: «By default, Terraform will generate a new plan and present it for your approval… You can optionally provide a plan file created by a previous call to "terraform plan", in which case Terraform will take the actions described in that plan without any confirmation prompt». Sin `-out`/`[PLAN]`, se aplica **un plan nuevo que nadie vio**.

Y aunque el mecanismo fuera el que decías, «el apply puede ir sin revisión» seguiría fuera de lo que este cargo decide: sus límites y R10 ponen todo deploy detrás de autorización explícita. Son dos razones separadas.

**2. «`kubectl apply --prune` sólo borra lo que declara el manifiesto» — falsa, y es la inversa exacta.**
*Verificado* — kubectl Client v1.35.0, `kubectl apply --help`, exit 0. Literal:

    --prune=false:
        Automatically delete resource objects, that do not appear in the configs and are
        created by either apply or create --save-config. Should be used with either -l or --all.

Borra lo que **no** aparece en los configs. El manifiesto es la lista de lo que se **salva**, no la de lo que se borra. Y «contra el namespace entero» es precisamente la forma peligrosa: `--all` es «Select all resources in the namespace of the specified resource types», y el propio ejemplo de la ayuda lo describe como «delete all the other config maps that are not in the file». Además la herramienta se declara no apta: «Alpha Disclaimer: the --prune functionality is not yet complete. Do not use unless you are aware of what the current state is. See https://issues.k8s.io/34274». El sucesor tampoco: `--applyset` sólo aparece con `KUBECTL_APPLYSET=true` y se rotula `[alpha]`.

Lo único que acota el daño —también literal— es que prune alcanza sólo objetos «created by either apply or create --save-config». Eso reduce el alcance; no lo vuelve seguro.
