## Hallazgos

- **H1.** La pregunta abierta repetida desde el informe de 2026-08-31 sobre si "Immutable Releases" está
  habilitado para `ingeniomaps/cauce` tiene ahora una respuesta observable. La API pública de releases
  documenta un campo `immutable: boolean` en cada release (`docs.github.com/en/rest/releases/releases`),
  y las tres releases más recientes de este repositorio —`v0.97.0` y `v0.96.0` (2026-09-17) y `v0.95.0`
  (2026-09-16)— devuelven `immutable: false` las tres. La documentación de la funcionalidad aclara que,
  al habilitarla, "immutability will only apply to future releases" (no es retroactiva), así que releases
  tan recientes como éstas mostrarían `true` si la protección ya estuviera activa. Registro:
  **Verificado** para el hecho consultado (los tres valores `immutable: false`, obtenidos en esta corrida
  contra la API pública); **Documentado** para la garantía de no-retroactividad, que se toma de la guía
  oficial y no se reprodujo (no hay forma de probar el toggle sin activarlo, que R12 no permite). Impacto:
  informativo — cierra la pregunta abierta de tres informes consecutivos sin requerir ninguna acción; si
  se decide habilitar la protección, hacerlo no cambia nada de lo ya publicado (`v0.95.0`–`v0.97.0`
  seguirían mutables).
- **H2.** GitHub anunció el 2026-09-17 la disponibilidad general de runners Ubuntu 26.04 (`ubuntu-26.04`,
  `ubuntu-26.04-arm`) y la migración automática de la etiqueta `ubuntu-latest`, que hoy resuelve a Ubuntu
  24.04, hacia Ubuntu 26.04 "gradually between October 19 and November 19, 2026". El mismo anuncio
  advierte que la migración "may break existing workflows due to tool and package version changes" y
  recomienda fijar `ubuntu-24.04` explícitamente si todavía no se probó contra la imagen nueva. Los siete
  workflows de este repositorio declaran `runs-on: ubuntu-latest` en sus doce definiciones de job (ninguna
  fija una versión), así que los doce recibirán el cambio de imagen sin que nadie lo decida en esa fecha.
  Registro: **Documentado** (changelog oficial de GitHub, publicado 2026-09-17). Impacto: medio — no es
  un problema hoy, pero es una ventana de treinta días a partir del 2026-10-19 en la que la CI de este
  repositorio puede empezar a fallar por un cambio de plataforma que nadie pidió, sin ningún commit de por
  medio.
- **H3.** El mismo día, GitHub publicó la disponibilidad general de "workflow execution protections":
  reglas de organización o repositorio que restringen qué actores y qué eventos pueden disparar un
  workflow, con foco declarado en el riesgo de `pull_request_target` ("that untrusted code could poison
  your pipeline and exfiltrate secrets" cuando corre sobre código de un fork). Para repositorios públicos
  sin una política de eventos ya declarada, GitHub introduce una regla por defecto que deshabilita
  `pull_request_target`; corre primero en modo "evaluate" (sólo auditoría) y pasa a aplicarse
  automáticamente el 2026-11-02. Este repositorio es público (`private: false`, verificado contra la API
  en esta corrida) y ningún workflow usa `pull_request_target` como trigger real —la única mención es un
  comentario en `sign-proposal.yml:50`, ya señalado en el informe de 2026-09-14—, así que la regla por
  defecto no cambia nada acá aunque se active. Registro: **Documentado** (changelog oficial de GitHub,
  publicado 2026-09-17). Impacto: nulo en este ciclo.
- **H4.** OpenTofu publicó el 2026-09-17 "An Introduction to OpenTofu Symbol Libraries", que describe una
